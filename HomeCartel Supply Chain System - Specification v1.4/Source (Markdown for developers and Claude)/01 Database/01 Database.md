# Database

Supabase Postgres. This file lists every table, its key fields and its purpose. Field types are Postgres types. Every table also has the **standard columns** below unless noted.

## 1. Naming and conventions

| Rule | Detail |
|---|---|
| Names | `snake_case`, singular nouns for columns, plural for tables (`purchase_orders`) |
| Primary key | `id uuid default gen_random_uuid()` |
| Human reference | Each main record also has a readable number, e.g. `PR-00123`, `PO-00045`, `SHP-00012`, `RCV-00031`, `PKG-01022`, `SR-00410`, `JOB-02231`, `EXC-00088`, `RR-00019`. Generated by a sequence per type. Staff quote these on the phone. |
| Money | `numeric(14,2)` in PHP unless a `currency` column says otherwise |
| Dates | `date` for business dates (Order Date, Target, Forecast), `timestamptz` for stamps |
| One name, one meaning | "Order Date" is always the customer's Books Sales Order date. The supplier PO date is `po_date`. Never use both "ship" and "shipment" for different things: shipping out of the factory is **shipout**, arriving into the warehouse is **receive**. |
| Deleting | No hard deletes of business records. Use `status = 'cancelled'` or `archived_at`. |
| Enums | Stored as `text` with a `check` constraint, or a small lookup table when Admin must edit the list |

### Standard columns (every business table)

| Column | Type | Rule |
|---|---|---|
| `created_at` | timestamptz | Set by the database once. Never edited. |
| `created_by` | uuid → staff | Set once |
| `updated_at` | timestamptz | Set by trigger on every write, including scripts and sync |
| `updated_by` | uuid → staff, or null | The person who made the last change |
| `updated_by_automation` | text | Name of the job if an automation made the change, e.g. `nightly_scan`, `books_sync` |

### Queue columns (every record that sits in a sorted queue)

Packages, delivery jobs, PO lines and shipments carry these. They are written **only by the sorting engine** (05 Shared Engines / 01).

| Column | Type | Meaning |
|---|---|---|
| `category` | text | Department category (see sorting engine) |
| `blocked_reason` | text | Set when category = `blocked` |
| `blocked_owner_id` | uuid → staff | Who must clear the block |
| `queue_rank` | int | 1 = do first, within the department queue |
| `priority_reason` | text | Plain words, e.g. "62 days old · 9 days past target · Broken" |
| `suggested_action` | text | e.g. "Release today", "Chase supplier", "Book Lalamove" |
| `suggested_release` | boolean | Above today's capacity cut line |
| `scored_at` | timestamptz | When the engine last scored it |

### The three dates (every record that carries a customer order)

`order_date date`, `order_age_days` (computed in views, stops when delivered), `target_delivery date`, `forecast_delivery date`, `forecast_window text` (e.g. "18–20 Nov"), `forecast_status text` (`on_time` / `at_risk` / `late`). Records that carry several Sales Orders (PO, shipment, receiving) store the **earliest** order date and target, and list each SO in their lines.

## 2. People, roles and settings

| Table | Purpose | Key fields |
|---|---|---|
| `staff` | Every user who logs in | `auth_user_id` (Supabase), `name`, `phone`, `email`, `active`, `home_warehouse_id`, `is_driver`, `is_installer`, `can_drive` |
| `roles` | Role list | `code` (`admin`, `supervisor`, `buyer`, `shipment_tracker`, `receiver`, `fulfillment_staff`, `fulfillment_supervisor`, `dispatcher`, `field`, `sales_agent`, `supplier_user`), `label` |
| `staff_roles` | Many-to-many | `staff_id`, `role_code` |
| `policy_settings` | Every tunable number and switch, shown in the Control Panel | `key` (unique), `label` (plain words), `value` (jsonb), `value_type`, `default_value`, `min_value`, `max_value`, `affects` (one sentence), `module`, `admin_only`, `updated_by`, `updated_at` |
| `policy_settings_history` | Old values kept | `key`, `old_value`, `new_value`, `changed_by`, `changed_at` |
| `audit_log` | Every sensitive change | `table_name`, `record_id`, `action`, `before` jsonb, `after` jsonb, `actor_id`, `actor_type` (`human`/`system`/`agent`), `at` |

## 9. Row-level security summary

| Data | Read | Write |
|---|---|---|
| `*_costing`, `supplier_quote_prices`, `truck_maintenance.cost` | admin, supervisor, buyer | buyer, admin |
| `so_payment_status` | admin, supervisor, dispatcher, sales agent (own customers) | `books_sync` only |
| Procurement tables | admin, supervisor, buyer; shipment_tracker: `shipments`, `shipment_lines`, shipment attachments only; supplier_user: own supplier's rows through portal views | buyer; tracker (shipment stage fields only); supplier (portal fields only) |
| Fulfillment tables | admin, supervisor, fulfillment roles | fulfillment roles |
| Delivery tables | admin, supervisor, dispatcher; field: own `delivery_jobs` through the field view | dispatcher; field (results, proofs, events only) |
| `sales_orders` | everyone internal through role views; sales agent: own customers | `books_sync`; sales agent and supervisor for promise changes through the API |
| `stage_events` | same as the record it belongs to | **server only** (never a user) |

Field users and suppliers never query tables directly. They read **views** (`field_jobs_v`, `portal_po_v`, …) that already exclude restricted columns.
